# PIZZA

4~9명이 즐기는 웹 추리 게임.

한 명이 제시어를 보고 **원형 캔버스**에 그림을 그린다. 그 그림은 **피자처럼 부채꼴로 잘려**
나머지에게 한 조각씩 흩어진다. 모든 조각은 **둥근 쪽이 위로 오게 회전되어** 있어서
자기 조각이 원본의 어느 방향이었는지 아무도 모른다.

자기 조각 하나만 보고 **먼저 알아맞히면 점수를 가져간다.** 빨리 맞힐수록 높은 점수다.

10점에서 시작해 **회차가 넘어갈 때마다 1점씩 깎인다.** 회차가 넘어가면 조각이 한 장씩
자동으로 늘어나므로, 깎이는 1점은 조각 한 장을 더 보는 값이다. 틀린 제출도 1점이다.

아직 못 맞힌 사람이 **전부 라운드 스킵을 누르면** 남은 시간을 건너뛰고 바로 다음 회차로
간다. 스킵을 누른 사람은 그 회차에 답을 낼 수 없다 — 실수로 점수를 잃지 않게 막아둔 것이다.

**출제자의 점수는 마지막 조립판에서만 나온다.** 조각을 제자리에 끼워 보여줬을 때
한 명이라도 맞히면 5점이고, 여러 명이 맞혀도 5점이다. 반대로 조각만 보고 다들 일찍
맞혀버리면 라운드가 조립판에 닿지 않아 0점이다 — **조각으로는 못 알아보지만 합치면
알아보는** 그림이 출제자에게 가장 좋은 그림이다.

출제자가 그리는 동안 기다리는 사람들은 **같이 낙서판**에 마음대로 그릴 수 있다.
낙서는 점수와도 제시어와도 아무 상관이 없고, 정답을 아는 쪽(출제자·관전자)에게는 보이지 않는다.

## 이야기

**결과 화면과 최종 화면에서만** 한마디씩 나눌 수 있다. 정답이 공개된 뒤라 새어 나갈 것이 없는
자리다. 회차 중에는 서버가 아예 받지 않는다 — 그 자리에는 정답을 아는 사람이 셋 있고
(출제자·관전자·먼저 맞힌 사람), 그중 하나가 한 줄만 흘려도 나머지가 공짜로 점수를 가져간다.

로그는 **한 판 내내 이어진다.** 라운드가 바뀌는 자리에 구분선이 들어가므로,
최종 화면에서 그 판 전체의 반응이 한눈에 되짚어진다. 한 판 더를 누르면 점수와 함께 비워진다.

이름 색은 낙서판에서 쓰던 그 색이다.

## 관전

**관전**을 고르면 그리지도 맞히지도 않고 출제자와 같은 것을 본다 — 제시어, 그려지는 원본,
남들이 무슨 조각을 들고 헤매는지까지. 인원에도 출제 순번에도 들어가지 않는다.

**로비에서만 고를 수 있다.** 그래서 게임 도중에 들어온 사람은 자동으로 관전자가 되고,
**모든 사람이 한 번씩 출제를 마쳐 판이 끝날 때까지** 관전으로 남는다. 로비로 돌아오면 그때 참여로 바꾼다.

관전자는 정답을 아는 사람이라 참가자 목록에 👁로 표시된다 — 통화 중에 흘릴 수 있는 사람이
누구인지 나머지가 알아야 하기 때문이다.

## 실행

```bash
npm install     # 처음 한 번만
npm run dev:all
```

**터미널 하나면 된다.** 게임 서버(8080), 페이지 서버(5173), 그리고 밖에서 들어올
터널까지 함께 뜬다. 친구에게 보낼 주소는 초록색으로 따로 크게 나온다.
끄려면 `Ctrl + C` 한 번 — 셋 다 같이 내려간다.

밖에서 들어올 일이 없으면 터널을 뺀다.

```bash
npm run dev     # 5173 + 8080 만
```

```
http://localhost:5173/
```

주소를 그대로 열면 **이름을 한 번 묻고 로비로 들어간다.** 로비에서 방을 만들거나
남의 방에 들어간다. 이름은 브라우저에 남아서 두 번째부터는 묻지 않는다.

방 안에서 **링크 복사**를 누르면 그 방으로 바로 가는 주소가 나온다.
`?room=코드`로 직접 들어가도 되고, 그때도 이름이 없으면 한 번 묻는다.
**4명 이상**이어야 시작할 수 있다.

자리는 브라우저에 남으므로 탭을 닫았다 들어와도 점수가 유지된다. 대신 같은 브라우저의
탭들이 한 자리를 나눠 쓰므로, 혼자 여러 창으로 시험할 때는 `&seat=2`처럼 자리 이름을 붙인다.

게임이 이미 진행 중이면 3명까지 계속 진행할 수 있다.

## 방장이 할 수 있는 것

- **시작**과 **다음 라운드** 넘기기
- **입장 잠그기** — 새 사람만 막는다. 끊겼다 돌아오는 사람은 통과한다.
- **내보내기** — 사람 이름 옆의 ✕. 그 브라우저는 그 방에 다시 못 들어오고, 방이 함께 잠긴다.
  방장이 언제든 풀 수 있다.

계정이 없는 웹이라 새 창을 열면 뚫린다. 막는 것이 아니라 **돌아오는 값을 올리는 장치**다.

## 윈도우에서

그대로 돌아간다. 네이티브 컴파일이 없어서 빌드 도구도 필요 없다.

- **Node 20.19 이상**이 필요하다 (또는 22.12 이상). `node -v`로 확인한다.
- `npm install` → `npm run dev` → `http://localhost:5173/?room=아무거나`
- 로그 앞의 `[서버] [화면]` 한글이 cmd.exe에서 깨져 보일 수 있다. 동작에는 영향이 없고,
  PowerShell이나 Windows Terminal을 쓰거나 `chcp 65001`을 한 번 치면 멀쩡해진다.
- 터널을 쓰려면 `cloudflared`를 따로 깔아야 한다: `winget install --id Cloudflare.cloudflared`

## 놀면서 동시에 고치기

친구들이 놀고 있는데 코드를 고치면 화면 서버가 모두의 브라우저를 새로고침해 버린다.
**안정된 판과 고치는 판을 따로 띄우면** 된다.

`git worktree`로 같은 저장소를 **다른 버전으로 한 벌 더** 꺼낸다. 복제가 아니라
같은 `.git`을 나눠 쓰는 것이라 새로 받을 것이 없다.

```bash
git worktree add ../PIZZA-play v1.3.0
ln -s ../PIZZA/node_modules ../PIZZA-play/node_modules
```

두 번째 줄은 패키지를 다시 받지 않으려는 것이다. 네이티브 컴파일이 없어서 그냥 이어도 된다.
윈도우처럼 링크가 번거로우면 그 자리에서 `npm install`을 한 번 하면 된다.

이제 두 터미널에서 각각 띄운다.

| | 어디서 | 명령 | 주소 |
|---|---|---|---|
| **놀이판** | `../PIZZA-play` | `npm run play:all` | `localhost:5174` + 터널 |
| **고치는 판** | `PIZZA` | `npm run dev` | `localhost:5173` |

포트가 갈려 있어 **서로 아무 상관이 없다.** 고치는 쪽을 아무리 저장해도 놀이판은 안 흔들린다.
친구에게 보낼 주소는 놀이판 터미널에 초록색으로 뜬다.

놀 버전을 바꾸려면 그 자리에서 갈아탄다.

```bash
cd ../PIZZA-play && git checkout v1.4.0
```

그림 기록(`data/drawings.jsonl`)은 판마다 따로 쌓인다. 놀이판에서 논 그림은
`../PIZZA-play/data/`에 있다.

다 놀았으면 치운다.

```bash
git worktree remove ../PIZZA-play
```

## 규칙 조절

`content/rules.json`의 값을 바꾸고 서버만 재시작한다.

| 값 | 뜻 |
|---|---|
| `minPlayers` | 시작에 필요한 최소 인원. 진행 중에는 이보다 하나 적어도 계속된다 |
| `maxPlayers` | 방 정원 |
| `sliceCountMin` | 조각 수의 최솟값. 맞히는 사람이 더 많으면 인원에 맞춰 늘어난다 |
| `drawSeconds` | 그리는 시간 |
| `guessSeconds` | 회차 한 번의 추론 시간 |
| `roundEndSeconds` | 결과 화면이 자동으로 넘어가는 시간. 0이면 방장이 직접 넘긴다 |
| `maxAttempts` | 라운드당 회차 수. 마지막 회차는 조립판이다 |
| `maxSlices` | 한 사람이 가질 수 있는 조각 수의 상한 (`maxAttempts - 1`이어야 한다) |
| `startScore` | 1회차에 맞혔을 때 받는 점수 |
| `attemptCost` | 회차가 하나 넘어갈 때마다 깎이는 점수 |
| `wrongSubmitCost` | 틀린 제출 한 번의 대가. 맞힌 제출은 공짜다 |
| `finalAttemptScore` | 마지막 조립판에서 맞혔을 때 주는 고정 점수 |
| `drawerScore` | 조립판에서 한 명이라도 맞혔을 때 출제자가 받는 점수 |

`minPlayers`는 **관전자를 빼고** 센다. 관전자 다섯에 참가자 둘로는 시작할 수 없다.

## 제시어

주제 **10개**, 단어 **500개** — 동물 · 음식 · 전자제품 · 직업 · 스포츠 · 자연 · 탈것 ·
건물 · 전통문화 · 이야기 속 존재. 주제마다 정확히 50개다.

늘리려면 `content/words/`에 JSON을 하나 더 넣는다.

```json
{ "topic": "악기", "words": ["기타", "피아노"] }
```

파일 이름 앞의 번호가 **화면에 뜨는 주제 버튼의 순서**다. 번호가 없으면 파일 이름의
알파벳순이 되어 한글로 보면 뒤죽박죽이 된다.

**같은 단어를 두 주제에 넣지 않는다.** 넣으면 그 단어의 주제가 뽑을 때마다 달라지는데,
맞히는 사람에게 주제는 힌트이므로 같은 그림에 다른 힌트가 붙는 셈이 된다.
`npm test`가 이것과 주제당 개수를 확인한다.

## 모이는 그림

라운드가 끝날 때마다 `data/drawings.jsonl`에 한 줄씩 쌓인다 — 제시어, 주제, 획, 맞힌 수.
나중에 *지난 그림 보기* 모드의 재료다. 커밋하지 않으므로 백업은 직접 해야 한다.
