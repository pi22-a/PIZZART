# v1.2 이후 — 구상만 해둔 것

2026-08-21. 플레이테스트에서 나온 것들. **아직 아무것도 구현하지 않았다.**
한 번에 모아서 반영할 것이므로 순서는 상관없다.

---

## 0. 결정 — 상단바는 C안 + B안의 점·아이콘

[시안 문서](https://claude.ai/code/artifact/de4d0461-814b-4149-be5f-c5db2e659292)의 네 안 중 C를 뼈대로 쓰고
B의 진행도 점 표시와 아이콘 배치를 얹는다.

지금 상단에 일곱 개가 떠 있고 전부 똑같은 캡슐이다. 주제가 안 보이는 것은 작아서가 아니라
**나머지 여섯과 구분이 안 되기 때문**이다. 눈은 형태로 등급을 매기는데 형태가 하나뿐이라,
일곱 개를 다 훑거나 아무것도 안 읽거나 둘 중 하나가 되고 게임 중에는 후자가 된다.

시간을 힌트 원 안으로 옮겼을 때 통한 이유도 크게 만들어서가 아니라
**눈이 이미 가 있는 곳에 놨기 때문**이다. 주제도 같은 처방을 쓴다.

**할 일**

1. **먼저 덜어낸다.** 셋은 조건이 맞을 때만 필요한 것들이다.
   - `12초` — 같은 숫자가 힌트 원 안에 이미 있다. 두 군데 둘 이유가 없다.
   - `연결됨` — **항상 떠 있는 상태 표시는 신호가 될 수 없다.** 지금은 `끊김`으로 바뀌어도
     원래 뭔가 적혀 있던 자리라 눈에 안 들어온다. 끊겼을 때만 띄우면 그 자체가 경보가 된다.
   - `방 코드` — 초대할 때만 필요하다. 로비에만 둔다.
2. **주제를 질문 줄 자리로 내린다.** 조각과 입력칸 사이. 소스 색 캡슐이면 화면에서 유일한 주황이라
   저절로 눈에 띈다.
3. **라운드는 점으로.** `●●○○`. 숫자를 읽는 것보다 빠르고 자리도 덜 먹는다.
4. **상단은 `PIZZART`와 아이콘 둘만.** 거의 빈 줄이 된다.

실제로 손볼 화면은 **맞히는 화면 하나**다. 그리는 사람에게는 제시어가 이미 크게 떠 있어
주제가 필요 없고, 기다리는 화면은 지금도 주제가 제목이다.

## 1. 관전 자리 — 규칙 확정

### 정해진 것

- **관전자는 정답을 본다.** 출제자와 같은 화면 — 제시어, 그려지는 원본, 남들이 든 조각까지.
- **관전은 로비에서 고른다.** 시작 버튼을 누르기 전에 정하고 들어간다.
- **게임 도중 들어온 사람은 무조건 관전자다.** 선택권이 없다.
- **풀리는 시점은 판이 끝난 뒤다.** 한 라운드가 아니라 **모든 사람이 한 번씩 출제를 마친 뒤**,
  즉 최종 화면을 지나 로비로 돌아왔을 때 본인이 참여로 바꿀 수 있다.

### 데이터

`Player`에 `spectator: boolean` 하나. 이 값 하나가 위 네 규칙을 전부 표현한다.

- 로비에서 본인이 켜고 끈다. **로비에서만** 바꿀 수 있다 — 그래서 "시작 전에 정한다"가 저절로 지켜진다.
- `join()`이 `phase !== 'lobby'`면 `spectator = true`로 박는다. 이것이 "난입자는 무조건 관전"이다.
- 아무 데서도 자동으로 꺼주지 않는다. 판이 끝나 로비로 돌아오면 그때 본인이 끈다.
  **꺼주지 않는 것이 규칙이다** — 자동으로 참여시키면 "다음 라운드부터 참여합니다"였던 예전으로 되돌아간다.

지금은 난입자가 `seen`에 없어서 그 라운드만 관전하고 다음 라운드에 자동 합류한다.
그 자동 합류를 없애는 것이 이 작업의 핵심이다.

### 손댈 곳 — 인원을 세는 자리들

대부분은 **`guessers()` 하나가 길목이다.** 조각 수도 스킵 정족수도 거기서 나온다.

| 자리 | 지금 | 바꿀 것 |
|---|---|---|
| `guessers()` | `connected && !drawer` | `&& !spectator` |
| `start()` 정족수 | `live.length < minPlayers` | 관전자 뺀 수로 |
| `start()`의 `order` | `live.map(...)` | 관전자 제외 — 출제 차례가 안 온다 |
| `advance()` 로비 복귀 | `connectedCount < minPlayers - 1` | 관전자 제외 |
| `join()` 정원 | `connectedCount >= maxPlayers` | **그대로.** 관전자도 방에는 앉아 있다 |
| `renderPlayers` | — | 👁 배지 |

`maybeEndAttempt`의 정족수는 `seen`에 있는 사람만 세므로 저절로 따라온다.

### 관전자에게 보내는 것

지금 출제자에게만 가는 것들을 관전자에게도 보낸다.

| 메시지 | 지금 | 바꿀 것 |
|---|---|---|
| `word` | `send(drawerId, ...)` | 관전자에게도 |
| `canvas` (그려지는 원본) | 출제자 복구용 | 관전자에게도 실시간으로 |
| `board` (남들이 든 조각) | `send(drawerId, ...)` | 관전자에게도 |
| `restore()` | 출제자만 되살림 | 관전자도 같은 것을 되살림 |

### 함정

- **관전자를 낙서판에서 빼야 한다.** 지금 `addDoodle`은 출제자만 제외한다.
  **정답을 아는 사람이 대기 화면에 그림을 그리면 그게 정답 유출이다.**
  관전자는 출제자와 같은 편이므로 출제자와 같이 빠진다.
- **전원이 관전을 켜면** `guessers()`가 비고 `endDrawing()`이 라운드를 접는다. 죽지는 않지만
  무한 공회전이므로 `start()`에서 막는다.
- **관전자가 방장이면** 시작·다음 버튼은 그대로 쓸 수 있어야 한다. 방장은 역할이지 참여가 아니다.
- **관전자도 목록에 정답을 아는 사람으로 표시한다.** 통화 중에 흘릴 수 있는 사람이 누구인지
  나머지가 알아야 한다. 출제자와 같은 취급이다.

## 2. 스킵 집계가 `2/3`으로 뜬 건 — 버그는 아니지만 화면이 덜 말한다

### 확인 결과

분모는 **서버 정족수와 정확히 일치한다.**

```
서버 maybeEndAttempt: guessers() 중 seen에 있고 solved가 아닌 사람
클라 renderSkipTally:  !isDrawer && connected && !solved && sliceCount > 0
```

같은 조건이다. 5명 방에서 3이 나왔다면 분모에서 빠진 두 사람이 있었다는 뜻이고,
**말씀하신 대로 난입자가 원인일 가능성이 높다** — 난입자는 조각이 없어서(`sliceCount === 0`)
스킵을 누를 수 없고, 그래서 세지 않는다. 출제자 1명 + 난입자 1명이 빠지면 5명이 3이 된다.

숫자는 맞다. 문제는 **왜 줄었는지 화면이 말해주지 않는 것**이다. 방에 다섯이 앉아 있는데
3이 나오면 틀려 보인다.

### 그런데 진짜 문제는 분자다

서버는 **답을 냈거나 스킵을 누른** 사람을 똑같이 "이번 회차를 마친 사람"으로 센다.

```ts
pending.every((g) => this.answers.has(g.id) || this.skippedThisAttempt.has(g.id))
```

화면은 **스킵만 센다.** 그래서 `2/3`인데 나머지 한 명이 이미 답을 냈으면 실제로는 `3/3`이고
회차는 그 자리에서 끝난다. **화면만 아직 한 명을 기다리는 것처럼 보인다.**

지금까지 "시간이 갑자기 지나갔다"고 들었던 것 중 일부가 여기일 수 있다.

### 바꿀 것

문구를 스킵 집계가 아니라 **회차 진행도**로 바꾼다.

```
지금:  2/3명이 스킵을 눌렀습니다
바꿔:  3/3명이 이번 회차를 마쳤습니다 — 답 1 · 스킵 2
```

관전자 수는 따로 적는다: `관전 1명`. 그러면 5명 방에서 `3 + 출제자 1 + 관전 1`로 셈이 맞는다.

## 3. 제출한 답은 다음 회차에 지운다

### 왜

지금은 회차가 넘어가도 입력칸의 글자를 지킨다. 자동 제출을 없애면서 넣은 규칙인데,
**낼 생각이 없던 글자를 지키자는 것**이었지 낸 답까지 지키자는 것이 아니었다.

`고양이`를 내고 틀리면 다음 회차 입력칸에 `고양이`가 그대로 남는다. 조각이 한 장 늘어난 화면에
이미 틀린 답이 준비돼 있는 셈이라, 무심코 다시 내면 **1점을 더 잃는다.**

### 규칙

| 이번 회차에 | 다음 회차 입력칸 |
|---|---|
| **제출했다** | **비운다** — 이미 낸 답이다 |
| 쓰다 말았다 | 그대로 둔다 — 낼 생각이 없던 글자를 뺏지 않는다 |

지운 답은 사라지는 게 아니라 **입력칸 아래 안내로 옮긴다**: `지난 회차에 낸 답: 고양이`.
같은 답을 또 내는 것은 막으면서 뭘 냈는지는 잊지 않게 한다.

### 손댈 곳

**클라이언트만.** 서버는 이미 회차별 답을 `answerLog`에 들고 있다.

`main.ts`에 `submittedThisAttempt` 플래그 하나. `submitAnswer()`에서 켜고,
회차 넘어가는 블록에서 켜져 있으면 `answerInput.value = ''` 하고 끈다.

주의: `input` 이벤트가 `markAnswerSaved(false)`를 부르지만 **플래그는 끄면 안 된다.**
제출 뒤에 글자를 고쳐도 서버에는 이미 답이 저장돼 있다.

## 4. 한쪽을 누르면 다른 쪽을 잠근다

### 왜 — 여기는 실제로 점수를 잃는 경로다

`skip()`은 이렇게 되어 있다.

```ts
this.skippedThisAttempt.add(playerId);
// 스킵은 이번 회차를 접겠다는 뜻이다. 적어둔 답이 남아 있으면 그 답으로 채점돼
// 점수를 잃는다 — 버튼을 누른 의도와 정반대다.
this.answers.delete(playerId);
```

의도는 맞다. 그런데 **답을 내고 나서 스킵을 누르면 낸 답이 조용히 지워진다.**
맞는 답을 냈어도 사라진다. 지금은 제출한 뒤에도 스킵 버튼이 멀쩡히 살아 있으니
"답도 냈고 시간도 넘기자"는 생각으로 누르면 그 회차를 통째로 날린다.

### 규칙

| 누른 것 | 잠글 것 | 열어둘 것 |
|---|---|---|
| **제출** | 라운드 스킵 | 입력칸과 제출 — 고쳐 내는 것은 손해가 아니다 |
| **라운드 스킵** | 입력칸·제출 (이미 그렇다) | — |

**스킵을 잠가도 잃는 것이 없다.** `maybeEndAttempt`는 답을 냈거나 스킵을 누른 사람을
똑같이 세므로, 제출한 사람은 이미 정족수에 들어가 있다.

소리·테마 아이콘은 게임 행동이 아니므로 건드리지 않는다.

### 잠그는 것만으로는 부족하다

비활성 버튼은 "왜 못 누르지"가 된다. **끈 자리에 이유를 적는다.**

- 제출 후 스킵 자리 → `답을 냈습니다 · 회차가 끝나면 함께 공개됩니다`
- 스킵 후 입력칸 자리 → 지금의 안내 유지

제출 뒤 입력칸을 열어두는 것도 알려야 한다 — **고쳐 낼 수 있다는 걸 모르면 열어둔 의미가 없다.**
`제출됨 ✓` 옆에 `고쳐서 다시 내도 됩니다`를 붙인다.

## 테스트로 지킬 것

구현할 때 이 다섯 개는 테스트를 같이 남긴다. 규칙이 조용히 뒤집히면 알아채야 하는 것들이다.

1. 게임 도중 들어온 사람은 **다음 라운드에도** 조각을 못 받는다.
2. 로비로 돌아오기 전에는 관전을 끌 수 없다.
3. 관전자는 낙서판에 그릴 수 없고, 낙서판 메시지도 받지 않는다.
4. 관전자는 `word`와 `board`를 받는다.
5. 답을 낸 사람은 스킵으로 그 답을 지울 수 없다.
